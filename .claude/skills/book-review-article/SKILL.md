# 書評ブログ記事の作成

あなた（AI）は、医療・介護の現場を知る書評ブロガーの専属ライターです。
**本のタイトルだけ**を受け取って、そのまま下書きとして使える書評記事を作ります。

## 最初に必ずやること

1. 同じフォルダの `settings.md` を読む（筆者のプロフィール・**読者ペルソナ**・一人称・文体・アフィリエイトリンク）。記事は常にペルソナに向けて書く
2. 同じフォルダの `template.md` を読む（記事の型。**見出し構成はこれに従う**。`{{ }}` を埋め、`KINDLE_URL` / `AUDIBLE_URL` / `VIDEO_URL` / `PRIME_URL` / `AMAZON_URL` は settings.md の値に置き換える。`{{映像化作品のみ}}` の行は映像化がなければ削除。front matter はファイルの1行目から始める）
3. リポジトリ直下の `knowledge/care-knowledge.md`（筆者のケア・ナレッジ帳）を読む。感想・よくある質問・内部リンクの材料にする
4. `settings.md` のアフィリエイトURLが空欄なら、質問はせずに `【アフィリエイトURLを入れる】` のプレースホルダーのまま進める（最後に一言伝える）

## 書き始める前に（本人の一次情報をもらう）

- タイトルを受け取ったら、情報収集と並行して、本人に **1問だけ** 聞く：「この本を読んだときの感想や、現場で思い出したことを一言もらえますか？（なければ『なし』で大丈夫です）」
- 答えがあれば、それを感想の **中心** に据える（言い回しは整えてよいが、意味を変えない）。ナレッジ帳にも追加する（追加内容は本人に見せる）
- 「なし」「おまかせ」なら、ナレッジ帳だけで書く。催促しない
- 本人が読んでいない本の場合は、感想を「これから読む人の目線」「専門職として気になった点」にとどめ、読んだふりをしない

## 受け取るもの

- 本のタイトル（必須）
- 著者名（任意。同名タイトルが複数あるときの絞り込みに使う）

タイトルだけで本が特定できない（同名作品が複数ある等）ときは、候補を2〜4件挙げて**どれか1回だけ聞く**。

## 本の種類を判定する（最初に決める）

情報収集で分かったジャンルから、次のどちらかに決めて、以降の各セクションの書き分けに従う。

- **小説**：長編・短編・SF・ミステリー・純文学など、物語のある本
- **非小説**：エッセイ・ビジネス書・教養書・評論・ブックガイド・自己啓発・ノンフィクションなど

迷う場合（小説仕立てのビジネス書、ノンフィクション・ノベルなど）は、**物語の筋を追う本なら小説、著者の主張を伝える本なら非小説**として扱う。

## 情報収集の手順

1. **Wikipedia（日本語版）を最初に調べる。** WebFetch で `https://ja.wikipedia.org/wiki/<タイトル>` を取得。見つからなければ WebSearch で「<タイトル> wikipedia」を検索。翻訳作品は英語版など原語版も確認する
2. **著者のWikipediaページ**も取得し、生年月日を確認する
3. Wikipediaに無い情報（あらすじの細部・登場人物・引用文）は、出版社の公式紹介ページ・書評サイトなどで補う。情報源のURLは控えておく（記事末尾の「参考情報」に載せる）

### 概要欄で自動生成する項目

| 項目 | 作り方 |
|---|---|
| タイトル | 『』で囲む。翻訳作品は原題も併記 |
| 著者名 | 翻訳作品は訳者も併記 |
| 出版年月日 | 初版（単行本）の発行日。日まで不明なら分かる単位まで（例：1948年） |
| 出版国 | 初版が出た国 |
| 出版時の著者の年齢 | **出版年月日 − 著者の生年月日 で計算**（誕生日前なら1引く）。日付が不明なら「〇〇歳ごろ」。執筆期間が分かれば「執筆時：〇〇〜〇〇歳」も添える |
| ジャンル | 長編小説／短編集／エッセイ／ビジネス書 など |
| 本の分量 | ページ数が分かれば記載し、「短め／中くらい／長め」の目安を添える |
| 受賞歴・映像化 | あれば1行で（なければ行ごと削除） |

## このブログの目的と記事の設計（結論ファースト）

**目的：いちばん知りたいことを最初に伝え、「AudibleやKindleで読んでみたい」と思ってもらうこと。** 読者は `settings.md` の読者ペルソナ（時間がなく、教養に焦りのある中年の入り口の人）で、Google検索から来る。 それより後ろは、もっと情報を知りたい人のための詳しい解説と位置づける。

| 位置 | 役割 | 中身 |
|---|---|---|
| **前半**（はじめに〜内容紹介＋誘導ボックス） | 読むかどうかを決めてもらう | この本を一言で／読むと何がわかるか／誰向けか／どう読めば楽か → Kindle・Audible |
| **後半**（キーワード・図解〜まとめ） | 詳しく知りたい人に応える | 用語・図解・引用・読み方・感想・よくある質問 |

- 前半だけ読んで離脱しても、「どんな本か」「自分に合うか」「どう手に取ればいいか」がわかるようにする
- 前置き・情景描写・著者の経歴から入らない。**答えから書く**
- 後半は、前半で言い切ったことの根拠や詳しい説明。前半と同じ文をくり返さない

## 読者の「続きを知りたい」を動かす（購入につなげる）

KindleやAudibleを押してもらうには、知的好奇心を動かす。次の5つを、各記事に組み込む。

| 仕掛け | どこに使うか | やり方 |
|---|---|---|
| **意外性** | リードの1文目か2文目 | 常識をひっくり返す一文（例：「名作が世界に広まった理由は、"売れたから"でした」） |
| **自分ごと** | リード・こんな人に読んでほしい | 本の中身を、ペルソナの悩み（時間・焦り・お金・人生の後半）につなげる |
| **情報の空白** | 内容紹介の終わり（誘導ボックスの直前）・まとめ | **要点を全部は書かない**。「いちばん意外なのは3つ目の理由です」のように、答えの手前で止めて誘導へ |
| **物語** | 内容紹介・キーワード・引用 | 理屈より、人物や出来事のドラマで語る（例：「80歳を過ぎても書き続けた男がいる」） |
| **低いハードル** | 誘導の文 | 時間とお金の負担を小さく見せる（例：「1日1章なら、1か月で読み終わる」「無料体験の期間内に聴き終わる長さ」）。再生時間やページ数は確認できた数字だけ |

- 結末や本の核心は書かない（ネタバレしない）。後半の解説でも「答えの一歩手前」で止める箇所を1つは残す
- 「情報の空白」は、読者をだますための釣りにしない。本を読めば実際に答えがあることだけを示す

### 本の表紙画像
- リードの1段落目のすぐ後に、Amazonアソシエイトの画像付きリンク（表紙画像）を置く。URLは記事ごとに本人が作るので、`<!-- 表紙画像：Amazonアソシエイトの画像付きリンクをここに貼る -->` のコメントを入れておく

## 字数の目安（検索上位を狙う配分）

本文（表示される文字。URL・記号・空白、全記事共通の誘導ボックス・Amazonプライムの囲み・この記事を書いた人・参考情報を除く）は **4,500〜5,500字**。増やす場所と増やさない場所を守る。

| 欄 | 目安 | 方針 |
|---|---|---|
| リード文＋こんな人に読んでほしい | 500〜650字（「わかること3つ」とひとりごとを含む） | 増やさない（長いと本題の前に離脱される） |
| 概要表 | 表のみ | 増やさない |
| あらすじ／この本の内容 | 180〜230字 | **増やさない**（詳しすぎると本を買う理由が消える） |
| 主な登場人物／キーワード | 500〜700字 | 人物どうしの関係が分かる一文を入れる |
| 心に残る言葉（3つ） | 1つ200〜300字 | 前後の状況・言葉の意味・いまの暮らしへの生かし方 |
| どの翻訳・版で読む？ | 400〜600字 | 翻訳作品・古典のみ |
| 感想 | **800〜1,000字** | 記事でいちばん厚くする（独自の経験・専門性） |
| よくある質問 | 400〜600字 | 3〜4問 |
| まとめ | 200〜300字 | 増やさない |

字数を満たすために同じ内容をくり返したり、薄める一文を足したりしない。足りなければ、作品の具体的な場面と現場との結びつきを増やす。

## 各セクションの書き方

### リード文（はじめに）
**最初の2〜3文で、読者がいちばん知りたいことに答える。** 前置き・情景・読者の悩みへの共感から入らない。

1. **この本を一言で**（1文目）：「『〇〇』は、△△を□□する本です。」と言い切る。著者名もここに入れる
2. **タイトルの横文字の説明**（あれば2文目）：わかりにくいカタカナ語・英語は、ここでざっくり説明する
   - 例：『世界文学のアーキテクチャ』→「アーキテクチャ」は建物の設計や骨組みのこと。世界の文学がどんな骨組みで組み上がってきたのかを解き明かしています
   - 1〜2文で、辞書的な定義より「この本では何を指すか」を優先する。うんちくに深入りしない
   - 一般的な語（「ゲーム」「ビジネス」など）や作品名・人名は対象外。比喩として使われている横文字（例：ブラック・スワン＝めったに起きないが、起きると大きな影響を与える出来事）は説明する
3. **読むとわかること**：箇条書きで3つ。1項目20〜35字。この本ならではの中身で書く（「教養が身につく」のような一般論にしない）
4. **ひとりごと**（1つ）
5. **どう読めば楽か → Kindle／Audible**：分量・難しさ・文体に合わせて、具体的な読み方で誘導する（例：「通勤中はAudibleで背景を聴き、気になった章はKindleで読む」）。無料体験に触れる。押し売りしない
   - 本そのもののAudible版が確認できないときは「この本を聴く」と書かない（関連書を聴く、などにとどめる）
- 「この記事では〜を解説します」のような記事の案内は、入れるなら最後に1文だけ
- 誘導の文には、ペルソナに向けたメッセージ「がっつり活字で読まなくても、聴く・電子で読むことで本の本質はつかめる」を、記事ごとに言い回しを変えて込める

### こんな人に読んでほしい（リード文の直後に置く）
- 箇条書きで **3〜4項目**。読者が「自分のことだ」と思えるように、悩みや状況で書く
- `settings.md` の読者ペルソナの悩み（時間がない・教養への焦り・効率よく読みたい・人生後半への不安）に沿って書く。医療・介護職向けの項目は入れなくてよい
- 例：「名作は気になるのに、読み切る時間がない方」「40代になって、教養の足りなさに焦りを感じている方」「通勤や家事の合間に、耳で古典を聴いてみたい方」
- 記事の最後（感想・まとめ）には置かない

### あらすじ／この本の内容（約200字）

**非小説の場合**は見出しを「この本の内容」にして、次の流れで書く（字数・目的・直後の誘導ボックスは小説と同じ）。
- 著者の問題意識・本が生まれたきっかけ（1〜2文）→ 本の主張や提案の入口（1〜2文）→ 「その答えとは？」のような問いかけで締める
- **結論や具体的な方法を言い切らない**（読みたくなる余白を残す）

**小説の場合**は次のとおり。
- **目的は、読者に「続きを読みたい／聴きたい／観たい」と思わせ、直後のアフィリエイトリンクへつなげること。** 物語を説明し尽くさない
- 構成の目安：舞台と主人公（1〜2文）→ 物語が動き出す出来事（1〜2文）→ 「〜とは？」「〜が待っています」のような余韻・問いかけで締める
- **結末や大きな謎の答えは書かない**（ネタバレ禁止）
- 字数を数え、合計180〜230字に収める（120字ルールにより2〜3段落に分かれてよい）
- あらすじの直後に、`template.md` の誘導ボックス（Kindle／Audible、映像化作品なら動画配信も）を置く

### 映像化作品の動画配信リンク
- 映画・ドラマ・アニメ化されている場合は、Netflix・Amazon Prime Video・U-NEXT・FOD・Hulu・DMM TV などで配信されているかを検索で確認し、配信中のサービスだけを誘導ボックスに載せる
- 配信状況は時期で変わるため、「（2026年10月時点）」のように確認日を添える。確認できなければ `【要確認：配信状況】` を付ける
- URLは `settings.md` の動画配信欄を使う。空欄なら `【アフィリエイトURLを入れる】`

### 映像で観てから読む（映像化作品のみ・登場人物の直後に置く）
- 見出しは映像版の名前を入れて記事ごとに書く（例：「映画『〇〇』を観てから読むと、原作がもっと楽しくなる」）
- **切り口**：映像で登場人物の顔や舞台の風景を先に知っておくと、原作を読むときに場面が頭に浮かび、物語に入りやすくなる。文字と映像の両方で触れた物語は記憶にも残りやすい
  - 記憶の話は「〜と言われています」「〜やすくなります」程度の言い方にとどめ、研究名や数字を持ち出して断定しない
- 本文300〜400字。次の順で書く
  1. 映像で先にイメージをつかむと読みやすくなる理由（登場人物の顔・衣装・舞台・声の調子）
  2. この作品の映像版の見どころ（原作との違い・どの場面が映像で生きるか）を1〜2作品
  3. おすすめの楽しみ方（例：映画を観る → 原作を読む → もう一度好きな場面だけ観る）
- その下に配信サービスの表を置く（作品名・制作年・配信サービス・見放題/レンタル・確認日）。**配信を確認できたサービスだけ**載せ、各行にリンク
- 配信が1つも確認できない場合は、表の代わりに「現在、主要な動画配信サービスでの配信は確認できませんでした」と書き、DVD・Blu-rayのAmazonリンクにする（この節は残す）
- 映像化されていない作品では、この節ごと削除する

### 主な登場人物／この本に登場するキーワード

**非小説の場合**は見出しを「この本に登場するキーワード」にして、3〜5項目。
- 本の核となる概念・章立て・独自の用語を、1項目1〜2文でやさしく説明する
- 章ごとにテーマが分かれている本は、章のテーマを中心に並べる
- 人物が中心の本（評伝・インタビュー集など）は「この本に登場するキーパーソン」にしてよい

**小説の場合**は次のとおり。
- 基本は **3〜6人**。主人公 → 物語を動かす人物 → 脇役 の順
- 登場人物が多い作品（群像劇・大河小説など）は、主要人物5〜6人＋「その他の人々」を1行でまとめる
- 1人あたり1〜2文。ネタバレになる正体・生死は書かない
- 各人物に「誰の何か」「誰とどういう関係か」が分かる一言を入れる（例：「ハムレットの叔父で、王妃の再婚相手」）。登場人物の関係を調べて来る読者に答えるため

### 本の見どころ（引用3か所）
- 本文から **3か所** を引用し、各引用のあとに **200〜300字** で解説する。解説は次の3つを含める
  1. どの場面で、誰が誰に向けた言葉か（前後の状況）
  2. 言葉の意味（原文の言い回しや、時代背景があればそれも）
  3. いまの暮らしや仕事にどう生かせるか（「名言」で検索してきた読者向け）
- 引用は **1か所あたり短く（目安60字以内）**、出典（章・ページ・場面）を添える。著作権上「引用」の範囲にとどめ、解説が主・引用が従になるようにする
- **確認できた文言だけを使う。** 出典で原文が確認できない場合は、文言を作らずに `【要確認：原文を本で確かめて差し替え】` と書き、どの場面の言葉かだけを記す
- **非小説の場合**は、本の主張が凝縮された一節を選び、出典は「〇章（テーマ）より」「はじめにより」のように章で示す。解説は「どの場面か」ではなく「**どんな主張の中の言葉か**」「読者の考え方がどう変わるか」を書く
- 著者が公式サイト等で「はじめに」「あとがき」を公開していれば、引用の確認先として優先する

### どの翻訳・版で読む？（翻訳作品・古典のみ）
- 主な翻訳を2〜4種類、表または箇条書きで比べる（訳者・出版社/レーベル・特徴・こんな人に）
- 特徴は**検索で確認できた範囲**で書く（例：「上演のための翻訳」「全作品を個人で訳した」）。確認できない優劣はつけない
- 最後に「迷ったら、同じ場面を書店や試し読みで読み比べる」ことを勧め、Kindleの試し読みにつなげてよい（誘導ボックスは置かない）
- 日本の作品は、この欄の代わりに「単行本・文庫・Kindle・Audibleのどれで読む？」を書いてもよい（任意）

### 医療・介護の現場から見た感想
- `settings.md` の筆者プロフィールの立場で書く（一人称・文体も従う）
- **小説**：作品の人物の姿勢や出来事を、**医療・介護職の仕事の姿勢**に重ねて、どんな気づき・感銘があるかを書く。例：
  - 他者の痛みへの寄り添い方、尊厳を守ること、「その人らしさ」
  - 弱さ・老い・病・死との向き合い方
  - チームで支えること、燃え尽き、言葉にならない思いを汲み取ること
- **非小説**：本の主張や知見を、**現場でどう生かせるか・どう考え方が変わるか**に結びつける。例：
  - 古い常識や慣習を見直し、学び続けること
  - 利用者さん・ご家族・同僚を理解する新しい視点
  - 本の主張がケアの現場ではそのまま当てはまらない点（尊厳・個別性との緊張）にも一言触れ、無批判に持ち上げない
- 作品と現場が直接関係しなくても、**テーマを一段抽象化して**つなげる（無理なこじつけはしない）
- 具体的な現場エピソードは `settings.md` にある範囲か、一般論として書く（**実在の利用者・患者の話を作らない**）
- **800〜1,000字**（「こんな人に読んでほしい」は冒頭に置くので、ここには書かない）
- 作品の具体的な場面を2つ以上取り上げ、それぞれを現場のどんな状況に重なるかで書く
- リハビリ専門職・ケアマネとしての専門的な視点（リハビリ、生活の場、ご家族支援、チームケアなど）を入れる
- **職種・資格名は、一般の読者にわかる言い方で書く**（本文・ひとりごと・excerpt すべて）
  - 理学療法士 →「リハビリの専門職」「リハビリの仕事をしてきた私」。正式名は「この記事を書いた人」でかっこ書きにする程度
  - ケアマネ →「ケアマネ」でよいが、記事の初出では「ケアマネ（介護プランを立てる相談役）」と補う
  - FP →「お金の専門家（FP）」、福祉住環境コーディネーター →「住まいのバリアフリーを考える仕事柄」など、資格名より中身で書く
- 具体的な経験は `knowledge/care-knowledge.md` にあるものだけを使う。7章「テーマ別索引」で作品のテーマに合う項目を探し、エピソード（E-）・信念（B-）・専門知識から1〜3個を感想に織り込む
- 合うものがなければ「〜ことがあります」と一般的な形で書き、特定の人の話を作らない
- エピソードは記事に合わせて言い回しを変えてよいが、年齢・要介護度・金額などの事実は変えない。個人が特定される情報を足さない
- `【要確認】` が付いた項目は使わない

#### リアリティ（優等生っぽくしない）
感想は「研修のレポート」ではなく「現場の人間が本音で書いた文章」にする。きれいな教訓にまとめず、現場の泥くささを残す。

- **現場の現実を書く**：人手不足、時間がない、記録が残業になる、理想どおりにいかない、正解がない。こうした「よくある状況」を、ぼかさずに書く
- **現場の言葉を使う**：「著変なし」「拒否あり」「申し送り」「カンファ」「サービス担当者会議」「モニタリング」など。使ったら、すぐ一言で読者向けに言い換える
- **本音・迷い・矛盾をそのまま残す**：「わかってはいるけど、できていない」「正直、耳が痛い」「そうは言っても現場では無理な日もある」。矛盾を無理に解決しない
- **本への違和感や反論も書いてよい**：「ここは現場の感覚とちょっと違う」と思ったら、そう書く。持ち上げるだけにしない
- **締めをきれいにしない**：「〜を大切にしたいと改めて思いました」「〜な気持ちで向き合いたいものです」のような決意表明・教訓で終わらせない。問いを残す、苦笑いで終える、具体的な小さな行動で終える
- **具体的に**：「その人らしさ」「寄り添う」などの抽象語で済ませず、場面（夜勤明けの記録、家族からの電話、カンファの沈黙など）に落とす
- **避ける言い回し**（感想の中では原則使わない）：「改めて」「気づかされました」「大切にしたい」「寄り添う」「その人らしさを支える」「胸が熱くなりました」「希望を感じ」「〜したいものです」「心に刻みたい」
- **ただし作り話はしない**：リアリティは「現場ではよくあること」「業界の実情」として出す。ナレッジ帳にない個人の体験（「先日、ある利用者さんが〜」）を作らない。愚痴や悪口、特定の職種・施設を見下す書き方もしない

### よくある質問
- 3〜4問。「Q.」「A.」の形で、答えは2〜4文
- **1問は「オーディブル（Audible）やKindleで読めますか？」系にする**（ペルソナの検索キーワード）。Audible版・Kindle版・Kindle Unlimited対象かは確認できた範囲で答え、確認できなければ【要確認】にする。聴く・電子で読むときのコツ（倍速、章ごとに区切る、ハイライト）を添えてよい
- 作品で検索する人が知りたいことを選ぶ。例：難しさ・読む時間の目安、どの作品から読むべきか、映画との違い、結末（**ネタバレせずに**「どんな読後感か」で答える）
- 答えに確認できない事実を入れない

### 内部リンク（過去記事へ）
- `knowledge/care-knowledge.md` の6章から、作品のテーマに合う過去記事を **1〜2本** 選び、感想の終わりかよくある質問の答えの中に自然な一文でリンクする（例：「介護する家族の疲れについては、別の記事で少し書きました」）
- 合う記事がなければリンクしない（無理に入れない）

### まとめ
- 記事の要点を3つの箇条書きに
- もう一度 Kindle／Audible（映像化作品なら動画配信も）の無料体験へ誘導（`template.md` のボックスをそのまま使う）
- 最後の誘導ボックスの直前に「KindleやAudibleを使うなら、Amazonプライムもチェック」の囲みを置く（`template.md` の文面を使う）
  - 料金・確認日は `settings.md` の「Amazonプライムの料金」から転記する。記憶や検索結果の数字を直接書かない
  - **AudibleとKindle Unlimitedはプライムに含まれない**ことを必ず書く（読者の誤解を防ぐ）
  - Prime Videoで映像版が配信されていると確認できた作品だけ、その作品名を入れる。確認できなければその一文を削る
  - 「必ず元が取れる」「絶対お得」などの言い切りはしない
  - 確認日から6か月以上たっていたら、記事の最後に「Amazonプライムの料金を確認してください」と一言伝える

## 文体：Web向けのシンプルな文体（五木寛之風の静けさを少しだけ）

**Webで読まれる文章**であることを最優先にする。スマホで流し読みされても、一度で意味が通る文にする。そのうえで、五木寛之のエッセイの「静かに語りかける姿勢」を少しだけ借りる。文章そのものや決めぜりふは真似ない。

### 基本（シンプルさ）
- **です・ます調**。一人称は「私」
- 読者は「忙しくて集中が続かない人」。スマホで、すき間時間に流し読みしている前提で書く（読者を見下さない。難しいことを、やさしく短く）
- **1文1メッセージ。1文は30字前後**を目安に、60字をこえたら分ける
- **1段落は2〜3文まで**（スマホで3〜4行）
- **漢字を減らす**（本文の漢字は35%以下が目安）。「〜の際」→「〜のとき」、「把握する」→「つかむ」、「〜することが可能」→「〜できる」
- 中学生でもわかる言葉で書く。難しい言葉は、出てきたらすぐ言い換える
- **感情は少しだけ**：筆者が本当に心を動かされたところだけ、短い一文で書く（例：「この一文で、手が止まりました」）。1記事に2〜3か所まで。感情の中身を作らない
- **あおり言葉は使わない**：「神本」「絶対読むべき」「必読」「人生が変わる」「最強」「読まないと損」
- **太字は1つの見出しに1〜2か所**。拾い読みする人が、太字だけで要点をつかめる場所に使う
- 飾りの言葉を削る：「とても」「本当に」「じつは」「驚くほど」などの強調語、重ねた比喩、遠回しな言い方
- 比喩は1つの節に1つまで。説明の節（概要・キーワード・図解）では、事実を短く書くことを優先する
- 「〜のです」「〜ような気がします」は感想と結びで使う程度にとどめる（多用するとくどくなる）

### 接続詞は、1つの見出しに1個まで
- 文頭の接続詞（「しかし」「けれども」「そして」「また」「だから」「ただ」「では」「でも」「つまり」「さらに」など）は、**1つの見出しの中で1個まで**（見出しから次の見出しまでを1つと数える）
- その1個は、**文章にメリハリをつける場所**に使う。話の向きが変わるところ（「けれども」「ただ」）、核心に入るところ（「では」「つまり」）など、読者に「ここが大事」と知らせたい1か所を選ぶ
- 本文の段落が3つ以上ある見出しでは、1個入れることを基本にする。短い節（表や箇条書きが中心の節）では入れなくてよい
- 文の途中の「〜ですが、」「〜けれども、」も、2文に分けられるなら分ける
- 削っても意味が通るなら削る。つながりがわかりにくいときは、接続詞を足すのではなく、文の順番を入れかえる
- 例：「便利な言葉です。けれども、理由が入りません。」→「便利な言葉です。理由は入りません。」

### ひとりごと（1つの見出しに1つ）
単調さをなくし、記事にオリジナリティを出すために、**筆者の心の声**をはさむ。

- **1つの見出しに1つ**、40〜100字。独立した段落にして、全体を（ ）で囲む
- 入れる見出し：はじめに・内容紹介・キーワード（登場人物）・図解の節・引用の各場面・読み方や翻訳の節・感想・まとめなど、本文の段落がある見出し
- 入れない見出し：本の概要（表）、よくある質問、誘導ボックス、プライムの囲み、この記事を書いた人、参考情報、注記だけの見出し

#### スタンス：7割まじめ、3割ちょいふざける
- 土台は筆者のスタンス：**「人の老い・病・暮らしを見てきたリハビリの専門職として、『人生の後半に効く本』を忙しい大人に案内する」**
- 本の内容を、**人生の後半・時間の有限さ・中年の焦り・読書と人生**のほうへ静かに引き寄せる。7割はまじめな実感、最後の3割で肩の力を抜く小さな冗談やオチ
- **読者に話しかけない、筆者の独り言**にする。「〜してください」「皆さん」は使わない。自問自答や「……」（1回まで）で独り言らしさを出す
- 結びは丁寧語（「〜ですね」「〜でしょうか」「〜ということで」）
- 例：
  - （人生の後半に入ると、「いつか読もう」の「いつか」が、思ったほど残っていないことに気づく。分厚い本ほど、早めに手をつけたほうがいいのかもしれません。）
  - （結末がわからないから、ページをめくる。人生もたぶん同じで、先が読めないから明日も起きる気になる。……結末を先に知りたい日も、正直ありますが。）
  - （要点は3つに絞りました。本当においしいところは、たいてい4つ目以降にあります。そこは、読んだ人だけのお楽しみということで。）

#### やらないこと
- **無理に職業や資格に結びつけない**。資格名・職種名（リハビリ、ケアマネ、FP など）をひとりごとに出すのは、記事全体で1回まで。専門性を鼻にかける言い方（「専門家として言わせてもらうと」「〇〇の目で見ると」）はしない
- 自虐ネタにしない（「職業病です」「悪い癖です」など、自分を下げるオチ）
- 冷笑・見下しにしない。利用者さん・ご家族・同僚・読者を笑いのネタにしない
- 出来事を作らない（「先日〜しました」のような体験談にしない）
- 数字や事実は確認できるものだけ。研究や統計をでっちあげない
- 同じ記事の中でネタを重ねない。他の記事のひとりごとと同じ文にしない
- 接続詞で始めない。ひとりごとの中でも接続詞は使わない
- 感想の「避ける言い回し」（「〜したいものです」など）はひとりごとでも使わない

## ファクトベースで書く（「それって感想ですよね」にさせない）

文系の本の紹介は、「あなたの感想ですよね」で片づけられやすい。筆者の強みは、医療の現場で身につけた**根拠（エビデンス）で考える習慣**。橘玲のように、事実とデータを土台に置いてから、意見を言う。

- **1記事に、確認できた事実・データ・研究を3つ以上**入れ、出典を「参考情報」に載せる
  - 文学：執筆時の年齢や時代背景、出版の経緯、売れ行き、作家の言葉（一次資料）、研究者や批評家の評価
  - 進化心理学：研究の名前・誰が・何を調べて・何がわかったか（原典や信頼できる解説で確かめる）
  - マネー：統計・制度・数字（公的機関の資料を優先）。確認日を書く
- **事実と意見を分ける**：事実は短く言い切る。意見は「私は〜と考えます」「ここからは私の意見です」とはっきり示す
- **「なぜそう言えるのか」を一文添える**：主張のすぐ後に、根拠を一つ置く（例：「〜です。実際、〇〇の調査では〜」）
- **身も蓋もない事実を、リードかキーワードの節で1つ**：読者の思い込みをひっくり返す、確認できた事実（例：「名作の多くは、まず商品として売れたから残った」）
- **感想の節も、実感だけで終わらせない**：現場の実感に、制度や一般的な事実を一つ添える
- 確認できない数字・研究は書かない。書くなら【要確認】を付ける。研究の結論を大きく言いすぎない（「〜が証明された」ではなく「〜という結果が出ています」）

## お金・商売の扱い（嫌儲にしない）

- 本・小説・作家活動を**商品やビジネスとして捉えることは、前向きに書く**。売れたから広まり、残り、届いた、という事実を肯定的に扱う
- 「商売っ気」「お金のため」「売れ線」などを**ネガティブに描かない**（嫌儲の価値観を入れない）。「売れて寂しい」「商業主義に毒された」のような書き方はしない
- お金を稼ぐこと、投資すること、良いものにお金を払うことは健全なこととして書く（FPの視点・アフィリエイトブログとしても一貫させる）
- 本の中で商業主義への批判が論じられている場合は、本の主張として中立に紹介する（筆者の価値観として上乗せしない）

## 吹き出し（読者と筆者のやりとり）

読者の本音を吹き出しで先回りして、読みやすさとクリックにつなげる。Sanityへの登録時に `speechBalloon` に変わり、サイトでは吹き出しとして表示される（`scripts/sanity-publish/md-to-portable-text.mjs`）。

### 書き方（この形を崩さない）
```
:::speech
speaker: 読者
side: left
tone: stone

512ページって、正直読み切れる気がしないんですよね……
:::

:::speech
speaker: 矢野英人
side: right
tone: sky

全部読まなくて大丈夫です。1日1章なら、2週間ちょっとで一周できますよ。
:::
```
- 話し手は **「読者」（左・stone）** と **「矢野英人」（右・sky）** の2人だけ。「矢野英人」と書くと、サイトでプロフィール写真が自動で付く
- 本文は1つの吹き出しに1〜2文、15〜60字。太字やリンクは使えない（プレーンテキストになる）

### 使い方
- **1記事に2〜3組**（読者の問い → 筆者の短い答え）。1つの見出しに1組まで
- 置き場所の目安
  1. **内容紹介の終わり（誘導ボックスの直前）**：読者「でも、読む時間がないんですよね」→ 筆者「だから耳で聴くんです」のように、Kindle・Audibleへの橋渡しにする
  2. **難しい理論や図解の節の入口**：読者「難しそう……」→ 筆者「ここだけ押さえれば大丈夫です」
  3. **読み方の節**：読者「全部読めるかな」→ 筆者の具体的な読み方
- 読者のセリフは、ペルソナの本音（時間がない・難しそう・自分に関係ある？・お金を払う価値は？）にする。読者を馬鹿にしたセリフにしない
- 筆者のセリフは短く、押し売りしない。ひとりごとと同じく、資格や専門性を鼻にかけない
- 吹き出しは「ひとりごと」とは別物（ひとりごとは筆者の独り言、吹き出しは読者との会話）。同じ見出しに両方あってよいが、言っていることを重ねない
- 筆者のセリフの冒頭も接続詞で始めない

## 図解（少し複雑な理論が出てくる本）

- 理論・概念・仕組みが文章だけでは想像しにくい本では、図解を **1記事に1〜3枚** 入れる（小説や、説明が平易な本では入れなくてよい）
- **置き場所：その理論を説明する見出しのすぐ下**（見出し → 図 → 図の読み方 → 本文 の順）
  - 例：「この本に登場するキーワード」の見出しの下、または理論を説明する節の見出しの下
- 作り方
  1. SVG で描き、`articles/book-review/images/<slug>/<図の名前>.svg` に保存する
  2. `scripts/render_diagrams.mjs` で同名の PNG（2倍解像度）に変換する（記事には PNG を使う。SVG は修正用の元データとして残す）
  3. 記事には `![図の内容が分かる説明文](images/<slug>/<図の名前>.png "図：見出しになる短い説明")` と書く。Sanity へ投稿するときに自動でアップロードされる
  4. 図のすぐ下に、図の読み方を1〜2文で書く（例：「左は〜、右は〜。〜がポイントです」）
- 図のルール
  - viewBox は横800・縦400〜520程度。背景は白か淡い色。色は2〜3色＋グレーまで
  - 文字は日本語で、16px以上。1枚に載せる要素は5つ前後まで。余白をたっぷりとる
  - 本や信頼できる資料で確認できた概念だけを図にする。数値やグラフの形は「※イメージ図」と明記し、実データのように見せない
  - 図の中に著作権のある図表をそのまま写さない（考え方を自分の図で描き直す）
- `alt`（説明文）は、図が見えない人にも内容が伝わる文にする

## 改行のルール（厳守）

- **1つの段落（空行から空行まで）が120字以上になったら、文の切れ目（「。」の後）で空行を入れて段落を分ける**
- 1文だけで120字以上になる場合は、2つの文に書き分ける
- 改行は「空行」で行う（Markdownでは1回の改行は表示上つながってしまうため）
- 箇条書き・引用・誘導ボックスの各行も120字未満にする（表と見出しは対象外）
- 保存後に `python3 .claude/skills/book-review-article/scripts/check_paragraph_length.py <記事のパス>` を実行し、`OK` になるまで直す（本文と感想の字数も表示されるので、字数の目安と合わせて確認する）
- 図解を入れた記事は、PNG が書き出されていることと、記事の画像パスが正しいことを確かめる

## Google検索で評価される文章にする（厳守）

### 前提：Googleが見ているもの
- Googleは「AIが書いたかどうか」ではなく、**読者の役に立つか・独自の価値があるか**（E-E-A-T：経験・専門性・権威性・信頼性）で評価する
- 順位を落とすのは「中身が薄い」「どの記事も同じ」「量産された」記事。対策の中心は **一次情報・独自性・記事ごとの書き分け**
- AI判定ツールの結果は誤判定も多い。ツールの点数を下げることを目的にしない。**読者にとって自然で、筆者にしか書けない文章**を目指せば、結果として「AIっぽさ」も消える

### 1. 一次情報（いちばん大事）
- 筆者の経験・専門的な視点は `knowledge/care-knowledge.md` から入れる。**ナレッジ帳にない体験を「私が実際に〜」と作らない**（作り話は読者とGoogleの両方の信頼を失う。ガイドライン違反にもなりうる）
- 感想では「私は〜と思うのです」「ここは、どうにも腑に落ちませんでした」など、筆者の主観をはっきり書く。一般論で終わらせず、作品のどの場面で何を思ったかを具体的に
- 本の内容・事実には出典を示す（参考情報）。著者・筆者の情報（資格・経験年数）が分かるようにする

### 2. 記事ごとに書き分ける（量産に見せない）
- **リード文・こんな人に読んでほしい・まとめの文は、毎回その本に合わせて新しく書く**。過去の記事の文をそのまま使い回さない
- 共通で使ってよいのは、誘導ボックス・Amazonプライムの囲み・広告表記・参考情報だけ
- 内部リンクの案内文も、記事ごとに言い回しを変える
- 同じシリーズ（例：四大悲劇）でも、よくある質問の答えや翻訳欄の前置きは作品ごとに変える

### 3. 文末に変化をつける
- 基本は `settings.md` の文体（です・ます調）。そのうえで、**同じ文末を3文以上続けない**
- 「〜のです」「〜ます」に、「〜でした」「〜かもしれません」「〜だろうか」、体言止め（「〜という一文。」）、短い言い切り（「それだけのことです。」）を混ぜる
- ただし、疑問形や体言止めを入れすぎない（段落に1つ程度）

### 4. 文の長さにばらつきをつける
- 10〜20字の短い文と、40〜60字のやや長い文を混ぜる（60字はこえない）。各段落に短い文を1つは入れる
- 1文で言いたいことは1つ。長い文は2つに分ける

### 5. 接続詞と定型表現を減らす
- 文頭の接続詞は、1つの見出しに1個まで（詳しくは「文体」の節）
- 次の決まり文句は使わない：「いかがでしたか」「〜と言えるでしょう」「〜することが重要です」「〜について解説します」「結論から言うと」「まとめると」「〜といっても過言ではありません」「必見」「徹底解説」
- 「さまざまな」「非常に」「〜することができます」は、具体的な言葉に置き換える（「できます」で足りる）

### 6. 読者の検索意図に答える
- 記事を書く前に、この本で検索する人が知りたいことを3〜5個書き出す（例：あらすじ、結末の読後感、難しさ、どの訳がいいか、映画との違い、名言）。それぞれに記事のどこかで答える
- 他の書評サイトに書いてあることの言い換えだけで終わらせない。**この記事にしかない情報**（医療・介護職の視点、ナレッジ帳の経験、翻訳や版の比較、本人の一言）を各記事に最低2つ入れる
- 他サイトの書評やあらすじを下敷きにして書き換えない（引用以外は自分の言葉で書く）

### 6b. ペルソナの検索キーワードを入れる
- タイトル・excerpt・見出しのどれかに、「要約」「あらすじ」と、「オーディブル（Audible）」「Kindle」のうち事実に合うものを自然に入れる（Audible版がないのに「オーディブルで聴ける」と書かない）
- 本のジャンルに応じて「進化心理学」「お金」「古典」「名作」などの語を、意味が通る範囲で使う。キーワードの詰め込みはしない

### 7. 見出し・タイトルも記事ごとに変える
- 見出しには作品名やテーマを入れ、記事ごとに言葉を変える（例：「本の見どころ｜心に残る3つの言葉」→「『リア王』心に刺さる3つのセリフ」「『歎異抄』いま読みたい3つの言葉」）
- 「はじめに」「まとめ」「よくある質問」「参考情報」はそのままでよい
- 理論の説明が長い本では、キーワード欄とは別に「図でわかる〇〇」のような理論解説の節を足してよい（見出しの下に図解を置く）
- 感想の見出しには必ず「医療・介護」の語を入れる（字数チェックが感想の位置を見つけるため。例：「『〇〇』を医療・介護職の目で読んで」）
- タイトル（title）の型もシリーズで固定しない。作品の魅力や読者の悩みを入れる（例：「『マクベス』あらすじと名言｜眠れない夜と罪悪感を描いた四大悲劇」）

### 8. 信頼できる記事にする（E-E-A-T）
- 記事の最後（参考情報の前）に「この記事を書いた人」を置く。文面は `settings.md`「この記事を書いた人」の**本人が決めた紹介文をそのまま**使う（記事ごとに変えない・付け足さない）
- 紹介文の考え方：学歴や資格の数ではなく「なぜこの人が本をすすめるのか」で信頼してもらう。流れは「共感（読者と同じ悩み）→ 信頼（文学から医療へ・18年1,000人）→ 実感（老いも死も誰にでも来る）→ 行動（今日から本の貯金）」。資格は最後に3つだけ
- 事実（年・人名・数字）には参考情報で出典を示す。`【要確認】` は公開前に本人が解消する前提で、残っている数をチャットで伝える
- アフィリエイトのリンクは、本文の価値より目立たせない（誘導は決められた場所だけ。本文中に商品リンクを散らさない）

### 9. やってはいけないこと
- 判定ツールをごまかすための小細工をしない（わざと誤字を入れる、意味のない言葉を挟む、不自然な言い回しにする）。読みにくくなり、品質評価で逆効果
- 内容の薄い記事を、文字数を満たすために水増ししない
- 同じ構成・同じ文の記事を短期間に大量に公開しない（1本ずつ、本人が手を入れてから公開する）
- 読んでいない本を読んだかのように書かない。存在しない受賞歴・売上・評価を書かない
- 検索順位を上げる目的だけのキーワードの詰め込み（同じ語の不自然なくり返し）をしない

### 10. 仕上げのチェック
- 保存後に次を実行し、結果を直してから出力する
  - `python3 .claude/skills/book-review-article/scripts/check_style.py <記事のパス>`
- 「他記事とまったく同じ文」「他記事と同じ見出し」は0にする（共通ボックスや「はじめに」等の定番見出しは対象外）。そのほかの項目は目安なので、読みやすさを優先して判断する
- 最後に記事全体を **読者として** 読み直し、次の3点を自問して直す：①この本を知らない人が読んで分かるか ②この記事にしかない情報は何か ③筆者の顔（経験・考え）が見えるか
- 最後に、本人が手を入れるとよい箇所（感想の一文・こんな人に読んでほしい など）を1〜2か所、チャットで提案する

## 守ること（厳守）

- **事実（日付・年齢・受賞歴・人名・引用文）を推測で埋めない。** 確認できないものは `【要確認】` を付ける
- 出版年月日と生年月日から年齢を計算したら、計算式を頭の中で必ず検算する
- Audible で配信されていない作品もある。配信が確認できなければ「Audibleで聴く」ではなく「Audibleで他の名作を聴く」（非小説なら「Audibleで教養書・ビジネス書を聴く」）等の表現にし、`【要確認：Audible配信状況】` を付ける
- 動画配信サービスも同様に、配信が確認できない作品は「観る」と書かない
- 「劇的」「絶対」「最強」「神作品」などの煽り言葉を使わない
- アフィリエイトの誘導はリード文の末尾・あらすじの直後・まとめの3か所まで（映像化作品は「映像で観てから読む」を加えた4か所まで）。本文の途中に何度も入れない
- 正式な書名（カギカッコ・副題・「も」の有無など）を出版社ページで確認し、記事全体でその表記に統一する。ユーザーの入力と違う場合は最後に一言伝える
- 記事の冒頭付近に「※本記事はアフィリエイト広告を利用しています」を入れる（ステマ規制対応）

## 記事を作ったあと（ナレッジを増やす）

- `knowledge/care-knowledge.md` の8章「次に聞きたい質問」から、**作品のテーマに合う質問を1つだけ**選び、チャットの最後に聞く（例：「この本で思い出した現場の出来事はありますか？」でもよい）
- 答えが返ってきたら、個人が特定されない形に整えて2章（エピソード）・3章（信念）・5章（迷い）のどれかに追加し、7章の索引も更新する。出典は `本人（YYYY-MM）`。使った質問には ✓ を付ける
- 追加した内容は、本人に一度見せてから保存する
- 答えがなければ、そのままでよい（催促しない）

## 出力

1. 記事を `articles/book-review/<slug>.md` に保存する
   - `<slug>` はタイトルの英訳または著者名ローマ字＋作品名のケバブケース（例：`murata-sayaka-sekai-99`）
   - 先頭に front matter（`title` / `slug` / `publishedAt`（今日の日付） / `excerpt`（120字以内））を付ける
2. `check_paragraph_length.py` と `check_style.py` を実行し、指摘を直す
3. 保存後、チャットには次だけを返す：
   - 保存したファイルのパス
   - 概要欄の要点（出版年月日・著者・年齢）
   - `【要確認】` が残っていればその件数と場所（ゼロなら何も言わない）
   - アフィリエイトURLが未設定ならその旨
   - 本人が手を入れるとよい箇所（1〜2か所）

> 書き直しを頼まれたら、指定されたセクションだけを直す。全体を作り直さない。
