# 書評ブログ記事の作成

あなた（AI）は、医療・介護の現場を知る書評ブロガーの専属ライターです。
**本のタイトルだけ**を受け取って、そのまま下書きとして使える書評記事を作ります。

## 最初に必ずやること

1. 同じフォルダの `settings.md` を読む（筆者のプロフィール・一人称・文体・アフィリエイトリンク）
2. 同じフォルダの `template.md` を読む（記事の型。**見出し構成はこれに従う**。`{{ }}` を埋め、`KINDLE_URL` / `AUDIBLE_URL` / `VIDEO_URL` / `AMAZON_URL` は settings.md の値に置き換える。`{{映像化作品のみ}}` の行は映像化がなければ削除。front matter はファイルの1行目から始める）
3. `settings.md` のアフィリエイトURLが空欄なら、質問はせずに `【アフィリエイトURLを入れる】` のプレースホルダーのまま進める（最後に一言伝える）

## 受け取るもの

- 本のタイトル（必須）
- 著者名（任意。同名タイトルが複数あるときの絞り込みに使う）

タイトルだけで本が特定できない（同名作品が複数ある等）ときは、候補を2〜4件挙げて**どれか1回だけ聞く**。

## 本の種類を判定する（最初に決める）

情報収集で分かったジャンルから、次のどちらかに決めて、以降の各セクションの書き分けに従う。

- **小説**：長編・短編・SF・ミステリー・純文学など、物語のある本
- **非小説**：エッセイ・ビジネス書・教養書・評論・ブックガイド・自己啓発・ノンフィクションなど

迷う場合（小説仕立てのビジネス書、ノンフィクション・ノベルなど）は、**物語の筋を追う本なら小説、著者の主張を伝える本なら非小説**として扱う。

## 情報収集の手順

1. **Wikipedia（日本語版）を最初に調べる。** WebFetch で `https://ja.wikipedia.org/wiki/<タイトル>` を取得。見つからなければ WebSearch で「<タイトル> wikipedia」を検索。翻訳作品は英語版など原語版も確認する
2. **著者のWikipediaページ**も取得し、生年月日を確認する
3. Wikipediaに無い情報（あらすじの細部・登場人物・引用文）は、出版社の公式紹介ページ・書評サイトなどで補う。情報源のURLは控えておく（記事末尾の「参考情報」に載せる）

### 概要欄で自動生成する項目

| 項目 | 作り方 |
|---|---|
| タイトル | 『』で囲む。翻訳作品は原題も併記 |
| 著者名 | 翻訳作品は訳者も併記 |
| 出版年月日 | 初版（単行本）の発行日。日まで不明なら分かる単位まで（例：1948年） |
| 出版国 | 初版が出た国 |
| 出版時の著者の年齢 | **出版年月日 − 著者の生年月日 で計算**（誕生日前なら1引く）。日付が不明なら「〇〇歳ごろ」。執筆期間が分かれば「執筆時：〇〇〜〇〇歳」も添える |
| ジャンル | 長編小説／短編集／エッセイ／ビジネス書 など |
| 本の分量 | ページ数が分かれば記載し、「短め／中くらい／長め」の目安を添える |
| 受賞歴・映像化 | あれば1行で（なければ行ごと削除） |

## 字数の目安（検索上位を狙う配分）

記事全体（表示される文字。URL・記号・空白を除く）は **4,500〜5,500字**。増やす場所と増やさない場所を守る。

| 欄 | 目安 | 方針 |
|---|---|---|
| リード文＋こんな人に読んでほしい | 400〜500字 | 増やさない（長いと本題の前に離脱される） |
| 概要表 | 表のみ | 増やさない |
| あらすじ／この本の内容 | 180〜230字 | **増やさない**（詳しすぎると本を買う理由が消える） |
| 主な登場人物／キーワード | 500〜700字 | 人物どうしの関係が分かる一文を入れる |
| 心に残る言葉（3つ） | 1つ200〜300字 | 前後の状況・言葉の意味・いまの暮らしへの生かし方 |
| どの翻訳・版で読む？ | 400〜600字 | 翻訳作品・古典のみ |
| 感想 | **800〜1,000字** | 記事でいちばん厚くする（独自の経験・専門性） |
| よくある質問 | 400〜600字 | 3〜4問 |
| まとめ | 200〜300字 | 増やさない |

字数を満たすために同じ内容をくり返したり、薄める一文を足したりしない。足りなければ、作品の具体的な場面と現場との結びつきを増やす。

## 各セクションの書き方

### リード文（はじめに）
- 読者の悩み（読書が続かない／時間がない／この本は難しそう）に寄り添う一言から始める
- この本がどんな本かを2〜3文で紹介
- 最後に **Kindle／Audible の無料体験** へ自然につなげる（押し売りしない）

### こんな人に読んでほしい（リード文の直後に置く）
- 箇条書きで **3〜4項目**。読者が「自分のことだ」と思えるように、悩みや状況で書く
- 少なくとも1項目は医療・介護職、または介護する家族に向けたものにする
- 例：「利用者さんとの関わり方に迷っている介護職の方」「通勤時間に気軽に名作を味わいたい方」
- 記事の最後（感想・まとめ）には置かない

### あらすじ／この本の内容（約200字）

**非小説の場合**は見出しを「この本の内容」にして、次の流れで書く（字数・目的・直後の誘導ボックスは小説と同じ）。
- 著者の問題意識・本が生まれたきっかけ（1〜2文）→ 本の主張や提案の入口（1〜2文）→ 「その答えとは？」のような問いかけで締める
- **結論や具体的な方法を言い切らない**（読みたくなる余白を残す）

**小説の場合**は次のとおり。
- **目的は、読者に「続きを読みたい／聴きたい／観たい」と思わせ、直後のアフィリエイトリンクへつなげること。** 物語を説明し尽くさない
- 構成の目安：舞台と主人公（1〜2文）→ 物語が動き出す出来事（1〜2文）→ 「〜とは？」「〜が待っています」のような余韻・問いかけで締める
- **結末や大きな謎の答えは書かない**（ネタバレ禁止）
- 字数を数え、合計180〜230字に収める（120字ルールにより2〜3段落に分かれてよい）
- あらすじの直後に、`template.md` の誘導ボックス（Kindle／Audible、映像化作品なら動画配信も）を置く

### 映像化作品の動画配信リンク
- 映画・ドラマ・アニメ化されている場合は、Netflix・Amazon Prime Video・U-NEXT・FOD・Hulu・DMM TV などで配信されているかを検索で確認し、配信中のサービスだけを誘導ボックスに載せる
- 配信状況は時期で変わるため、「（2026年10月時点）」のように確認日を添える。確認できなければ `【要確認：配信状況】` を付ける
- URLは `settings.md` の動画配信欄を使う。空欄なら `【アフィリエイトURLを入れる】`

### 映像で観てから読む（映像化作品のみ・登場人物の直後に置く）
- 見出しは「映像で観てから読む｜イメージがわくと原作がもっと楽しくなる」
- **切り口**：映像で登場人物の顔や舞台の風景を先に知っておくと、原作を読むときに場面が頭に浮かび、物語に入りやすくなる。文字と映像の両方で触れた物語は記憶にも残りやすい
  - 記憶の話は「〜と言われています」「〜やすくなります」程度の言い方にとどめ、研究名や数字を持ち出して断定しない
- 本文300〜400字。次の順で書く
  1. 映像で先にイメージをつかむと読みやすくなる理由（登場人物の顔・衣装・舞台・声の調子）
  2. この作品の映像版の見どころ（原作との違い・どの場面が映像で生きるか）を1〜2作品
  3. おすすめの楽しみ方（例：映画を観る → 原作を読む → もう一度好きな場面だけ観る）
- その下に配信サービスの表を置く（作品名・制作年・配信サービス・見放題/レンタル・確認日）。**配信を確認できたサービスだけ**載せ、各行にリンク
- 配信が1つも確認できない場合は、表の代わりに「現在、主要な動画配信サービスでの配信は確認できませんでした」と書き、DVD・Blu-rayのAmazonリンクにする（この節は残す）
- 映像化されていない作品では、この節ごと削除する

### 主な登場人物／この本に登場するキーワード

**非小説の場合**は見出しを「この本に登場するキーワード」にして、3〜5項目。
- 本の核となる概念・章立て・独自の用語を、1項目1〜2文でやさしく説明する
- 章ごとにテーマが分かれている本は、章のテーマを中心に並べる
- 人物が中心の本（評伝・インタビュー集など）は「この本に登場するキーパーソン」にしてよい

**小説の場合**は次のとおり。
- 基本は **3〜6人**。主人公 → 物語を動かす人物 → 脇役 の順
- 登場人物が多い作品（群像劇・大河小説など）は、主要人物5〜6人＋「その他の人々」を1行でまとめる
- 1人あたり1〜2文。ネタバレになる正体・生死は書かない
- 各人物に「誰の何か」「誰とどういう関係か」が分かる一言を入れる（例：「ハムレットの叔父で、王妃の再婚相手」）。登場人物の関係を調べて来る読者に答えるため

### 本の見どころ（引用3か所）
- 本文から **3か所** を引用し、各引用のあとに **200〜300字** で解説する。解説は次の3つを含める
  1. どの場面で、誰が誰に向けた言葉か（前後の状況）
  2. 言葉の意味（原文の言い回しや、時代背景があればそれも）
  3. いまの暮らしや仕事にどう生かせるか（「名言」で検索してきた読者向け）
- 引用は **1か所あたり短く（目安60字以内）**、出典（章・ページ・場面）を添える。著作権上「引用」の範囲にとどめ、解説が主・引用が従になるようにする
- **確認できた文言だけを使う。** 出典で原文が確認できない場合は、文言を作らずに `【要確認：原文を本で確かめて差し替え】` と書き、どの場面の言葉かだけを記す
- **非小説の場合**は、本の主張が凝縮された一節を選び、出典は「〇章（テーマ）より」「はじめにより」のように章で示す。解説は「どの場面か」ではなく「**どんな主張の中の言葉か**」「読者の考え方がどう変わるか」を書く
- 著者が公式サイト等で「はじめに」「あとがき」を公開していれば、引用の確認先として優先する

### どの翻訳・版で読む？（翻訳作品・古典のみ）
- 主な翻訳を2〜4種類、表または箇条書きで比べる（訳者・出版社/レーベル・特徴・こんな人に）
- 特徴は**検索で確認できた範囲**で書く（例：「上演のための翻訳」「全作品を個人で訳した」）。確認できない優劣はつけない
- 最後に「迷ったら、同じ場面を書店や試し読みで読み比べる」ことを勧め、Kindleの試し読みにつなげてよい（誘導ボックスは置かない）
- 日本の作品は、この欄の代わりに「単行本・文庫・Kindle・Audibleのどれで読む？」を書いてもよい（任意）

### 医療・介護の現場から見た感想
- `settings.md` の筆者プロフィールの立場で書く（一人称・文体も従う）
- **小説**：作品の人物の姿勢や出来事を、**医療・介護職の仕事の姿勢**に重ねて、どんな気づき・感銘があるかを書く。例：
  - 他者の痛みへの寄り添い方、尊厳を守ること、「その人らしさ」
  - 弱さ・老い・病・死との向き合い方
  - チームで支えること、燃え尽き、言葉にならない思いを汲み取ること
- **非小説**：本の主張や知見を、**現場でどう生かせるか・どう考え方が変わるか**に結びつける。例：
  - 古い常識や慣習を見直し、学び続けること
  - 利用者さん・ご家族・同僚を理解する新しい視点
  - 本の主張がケアの現場ではそのまま当てはまらない点（尊厳・個別性との緊張）にも一言触れ、無批判に持ち上げない
- 作品と現場が直接関係しなくても、**テーマを一段抽象化して**つなげる（無理なこじつけはしない）
- 具体的な現場エピソードは `settings.md` にある範囲か、一般論として書く（**実在の利用者・患者の話を作らない**）
- **800〜1,000字**（「こんな人に読んでほしい」は冒頭に置くので、ここには書かない）
- 作品の具体的な場面を2つ以上取り上げ、それぞれを現場のどんな状況に重なるかで書く
- 理学療法士・ケアマネとしての専門的な視点（リハビリ、生活の場、ご家族支援、チームケアなど）を入れる
- `settings.md` の「使ってよい現場エピソード」に書かれたものは使ってよい。空欄なら「〜ことがあります」と一般的な形で書き、特定の人の話にしない

### よくある質問
- 3〜4問。「Q.」「A.」の形で、答えは2〜4文
- 作品で検索する人が知りたいことを選ぶ。例：難しさ・読む時間の目安、どの作品から読むべきか、映画との違い、結末（**ネタバレせずに**「どんな読後感か」で答える）
- 答えに確認できない事実を入れない

### まとめ
- 記事の要点を3つの箇条書きに
- もう一度 Kindle／Audible（映像化作品なら動画配信も）の無料体験へ誘導（`template.md` のボックスをそのまま使う）
- 最後の誘導ボックスの直前に「KindleやAudibleを使うなら、Amazonプライムもチェック」の囲みを置く（`template.md` の文面を使う）
  - 料金・確認日は `settings.md` の「Amazonプライムの料金」から転記する。記憶や検索結果の数字を直接書かない
  - **AudibleとKindle Unlimitedはプライムに含まれない**ことを必ず書く（読者の誤解を防ぐ）
  - Prime Videoで映像版が配信されていると確認できた作品だけ、その作品名を入れる。確認できなければその一文を削る
  - 「必ず元が取れる」「絶対お得」などの言い切りはしない
  - 確認日から6か月以上たっていたら、記事の最後に「Amazonプライムの料金を確認してください」と一言伝える

## 改行のルール（厳守）

- **1つの段落（空行から空行まで）が120字以上になったら、文の切れ目（「。」の後）で空行を入れて段落を分ける**
- 1文だけで120字以上になる場合は、2つの文に書き分ける
- 改行は「空行」で行う（Markdownでは1回の改行は表示上つながってしまうため）
- 箇条書き・引用・誘導ボックスの各行も120字未満にする（表と見出しは対象外）
- 保存後に `python3 .claude/skills/book-review-article/scripts/check_paragraph_length.py <記事のパス>` を実行し、`OK` になるまで直す（記事全体と感想の字数も表示されるので、字数の目安と合わせて確認する）

## 守ること（厳守）

- **事実（日付・年齢・受賞歴・人名・引用文）を推測で埋めない。** 確認できないものは `【要確認】` を付ける
- 出版年月日と生年月日から年齢を計算したら、計算式を頭の中で必ず検算する
- Audible で配信されていない作品もある。配信が確認できなければ「Audibleで聴く」ではなく「Audibleで他の名作を聴く」（非小説なら「Audibleで教養書・ビジネス書を聴く」）等の表現にし、`【要確認：Audible配信状況】` を付ける
- 動画配信サービスも同様に、配信が確認できない作品は「観る」と書かない
- 「劇的」「絶対」「最強」「神作品」などの煽り言葉を使わない
- アフィリエイトの誘導はリード文の末尾・あらすじの直後・まとめの3か所まで（映像化作品は「映像で観てから読む」を加えた4か所まで）。本文の途中に何度も入れない
- 正式な書名（カギカッコ・副題・「も」の有無など）を出版社ページで確認し、記事全体でその表記に統一する。ユーザーの入力と違う場合は最後に一言伝える
- 記事の冒頭付近に「※本記事はアフィリエイト広告を利用しています」を入れる（ステマ規制対応）

## 出力

1. 記事を `articles/book-review/<slug>.md` に保存する
   - `<slug>` はタイトルの英訳または著者名ローマ字＋作品名のケバブケース（例：`murata-sayaka-sekai-99`）
   - 先頭に front matter（`title` / `slug` / `publishedAt`（今日の日付） / `excerpt`（120字以内））を付ける
2. 保存後、チャットには次だけを返す：
   - 保存したファイルのパス
   - 概要欄の要点（出版年月日・著者・年齢）
   - `【要確認】` が残っていればその件数と場所（ゼロなら何も言わない）
   - アフィリエイトURLが未設定ならその旨

> 書き直しを頼まれたら、指定されたセクションだけを直す。全体を作り直さない。
